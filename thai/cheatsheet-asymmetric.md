## 0. แพลตฟอร์ม 60 วินาที

```python
pow(a, e, n)                 # modexp ดั้งเดิม - ห้ามใช้ a**e % n กับตัวเลขจำนวนมาก
d = pow(e, -1, phi)          # หลาม 3.8+; gcd(e, phi) ต้องเป็น = 1
from Crypto.Util.number import long_to_bytes, bytes_to_long
m = pow(c, d, n); print(long_to_bytes(m))
```

**φ เป็นไปตามโครงสร้างของ n** — ขั้นตอนแรกคือการถามว่า "จริงๆ แล้ว n คืออะไร" เสมอ:

| n | φ(n) | หมายเหตุ |
|---|---|---|
| p·q (ต่างๆ) | (p−1)(q−1) | มาตรฐาน |
| p (n ไพรม์) | n − 1 | เคล็ดลับคำถามที่มี n "วิเคราะห์ไม่ได้" |
| p² | p·(p−1) | **ไม่ใช่ (p−1)²**; p = isqrt(n) |
| Π pᵢ (หลายจำนวนเฉพาะ) | Π (หน้า − 1) | คูณด้วยตัวประกอบ FULL รวมทั้งตัวคูณ |

d ต้องการเพียงทำตาม mod lcm(p−1, q−1) เพื่อถอดรหัส — มีประโยชน์ในกรณีที่เกิดข้อผิดพลาดเล็กน้อย

## 2. การวิเคราะห์ N — ระดับขั้น

ลำดับที่ควรลองคือ **เสมอ**: ป้ายกำกับพิเศษ → factordb → Fermat → p−1 → ECM → เครื่องมือสังเคราะห์ เธรดที่ "สะอาด" ใดๆ ก็มีสัญญาณที่ต้นทางด้วย (ดูตารางที่ 11)

### 2.1 แฟคเตอร์db

```python
from factordb.factordb import FactorDB
f = FactorDB(n); f.connect()
print(f.get_status(), f.get_factor_list())   # สถานะ 'C' = ยังไม่เสร็จสิ้นการแยกตัวประกอบ
# รายการสามารถประกอบด้วยปัจจัย COMPOUND — ตรวจสอบ p*q == n ด้วยตนเองเสมอ และกำหนดให้แต่ละปัจจัยเป็นสำคัญ
```

โดยปกติแล้ว n ต่ำกว่า ~ 256 บิตจะมีอยู่ในฐานข้อมูล 150 บิตเกือบจะแน่นอน

### 2.2 แฟร์มาต์ (p ≈ q)

```python
from gmpy2 import isqrt
def fermat(n, max_iter=10**6):
    a = isqrt(n)
    if a*a < n: a += 1
    for _ in range(max_iter):
        b2 = a*a - n
        b = isqrt(b2)
        if b*b == b2: return int(a-b), int(a+b)
        a += 1
```

สัญญาณ: `next_prime(p)`, q สร้างขึ้นจากฐานเดียวกัน, มีบาลานซ์ขนาดใหญ่ที่ DB ไม่มี วิ่งสัก 1–2 นาทีก่อนที่จะคิดอีกครั้ง — ราคาถูกมากเมื่อเทียบกับการโจมตีแบบนั่งร้านอื่นๆ Gotcha: PARI/GP `factorint` **ทำ** มีขั้นตอน Fermat แรก (ลำดับจริง: การแบ่งการทดลอง → Rho/SQUFOF → ECM → MPQS) — ด้วย N ที่สมดุล 8192 บิต มันจะค้างตลอดไป ในขณะที่หลาม 5 บรรทัดจะเข้าสู่รอบที่ 1 ค่าสถานะ PARI หากถูกบังคับ: 1=avoid MPQS, 2=avoid Stage 1 ECM, 4=avoid Rho/SQUFOF, 8=bỏ ECM สุดท้าย

### 2.3 พอลลาร์ด p−1 (p−1 เรียบ)

```python
def pollard_p1(n, B=65536):
    a = 2
    for j in range(2, B):
        a = pow(a, j, n)
        g = gcd(a - 1, n)
        if 1 < g < n: return g
```

สัญญาณ: `p = M + 1` พร้อมด้วย M = สะสมจำนวนเฉพาะขนาดเล็ก รวม p+1 (วิลเลียมส์) หากคุณเสนอให้สร้างไพรม์ชนิดพิเศษ โดยทั่วไป B = 65536 จะเพียงพอสำหรับเธรด CTF

### 2.4 รูปแบบพิเศษของ N

- **N ใกล้ยกกำลัง 2 / รูปแบบพหุนาม**: แปลงเป็นพหุนามด้วยฐาน 2 แล้วแยกตัวประกอบพหุนาม (Sage):
  ```python
  poly = sum(e * x^i for i, e in enumerate(n.digits(2)))
  print(poly.factor())     # ตัวประกอบพหุนาม → ลอง mod อีกครั้ง ฐาน 2^k
  ```
- **จำนวนเฉพาะ Mersenne**: p, q ∈ list ~51 จำนวนเฉพาะ Mersenne 2^k − 1 ทราบ → การทดลองหารรายการทั้งหมด (k ถึง 82589933)
- **N บิต/การทำซ้ำที่ดี**: ลองหารด้วยหมายเลขหน่วยซ้ำ 2^k±1.

### 2.5 ECM / เครื่องมือสังเคราะห์

- PARI: `factor(n)` มีค่าประมาณ ~60–70 หลัก; ปราชญ์มี `ecm(B1)`
- RsaCtfTool: `--attack all` ทำงานช้าเพียงไม่กี่นาที — การคาดเดาว่าการวิเคราะห์พฤติกรรมจะระบุการโจมตีได้อย่างถูกต้อง

## 3. Sinh Prime มีโครงสร้างการฆ่าตัวตาย =

- **ROCA (Infineon)**: `p = k·M + 65537^a mod M`, M = ไพรม์ 40 ไพรม์ ไพรม์อาศัยอยู่ในชุดย่อยที่มีโครงสร้างขนาดเล็ก ⟹ การขุด Coppersmith (`rocapolice`/การโจมตีแบบเข้ารหัสลับ) N ขนาดเล็ก (511 บิต) จากนั้น factordb ก็พร้อมใช้งาน
- **Cheng 4p−1**: `4p − 1 = D·s²` (D squarefree, หมายเลขคลาสขนาดเล็ก เช่น 427) → แยกตัวประกอบด้วยวิธีคูณเชิงซ้อน (การคูณเชิงซ้อน ลำดับลูคัส + gcd): `crypto-attacks/attacks/factorization/complex_multiplication.py` นี่เป็นรูปแบบหนึ่งของ "ประตูหลังโดยเจตนา"
- **ไพรม์ที่ใช้ร่วมกันระหว่างคีย์ (เอนโทรปีไม่ดี)**: แบตช์ GCD —
  ```python
  for i, j in combinations(range(len(ns)), 2):
      g = gcd(ns[i], ns[j])
      if g != 1: p, q = g, ns[i] // g     # เสร็จสิ้นการแยกตัวประกอบ 2 คีย์พร้อมกัน
  ```
Gotcha: ~ ไม่กี่โหลคู่สามารถแชร์ >1 ไพรม์ (gcd คอมโพสิต) — กรอง `g.bit_length() == n.bit_length()//2` หรือตรวจสอบ `isprime(g)` ก่อนที่จะเชื่อ

## 4. มีขนาดเล็กและไม่มีช่องว่างภายใน

- **e = 1**: `c = m mod n` — ไม่มีการเข้ารหัสเลย `long_to_bytes(c)` เสร็จแล้ว
- **m^e < n** (ไม่ได้ห่อ): `m, ok = gmpy2.iroot(c, e); assert ok` — **ตรวจสอบแฟล็กที่แน่นอนเสมอ**, iroot ไม่แน่นอนหมายถึงถูกห่อ (หรือทิศทางผิด)
- **การออกอากาศแบบ Håstad**: m เดียวกัน, e เดียวกัน, ≥ e โมดูลัสของสององค์ประกอบร่วมกัน:
  ```python
  from itertools import combinations
  for grp in combinations(zip(ns, cs), e):
      N = prod(n for n, _ in grp)
      M = sum(c * pow(N//n, -1, n) * (N//n) for n, c in grp) % N   # ซีอาร์ที
      m, ok = gmpy2.iroot(M, e)
      if ok: print(long_to_bytes(m))
  ```
Gotcha: ไม่ใช่ว่าทูเพิลทั้งหมดจะมี m เหมือนกัน หากคุณต้องการผสมสัญญาณรบกวน ให้บรูตองค์ประกอบ e ทุกชุดรวมกัน และตรวจสอบแฟล็กคำนำหน้า
- **Padding null (ทราบล่วงหน้า)**: m = FLAG ∥ 0^k ⟹ c ≡ FLAG³·256^{3k}: คูณด้วย `pow(256**(3*k), -1, n)` จากนั้นค่าจริงคือ `t + j·n` โดยมี j เล็ก — brute j แล้ว `iroot`:
  ```python
  for flag_len in range(20, 81):
      t = c * pow(256**(3*(100-flag_len)), -1, n) % n
      for j in range(2**24):
          m, ok = gmpy2.iroot(t + j*n, 3)
          if ok and long_to_bytes(m).startswith(b"crypto{"): ...
  ```
ข้อความตายตัวที่เทียบเท่ากับ Coppersmith (x³ − t, sage `small_roots`) — brute j เขียนง่ายกว่าและเร็วเพียงพอเมื่อมีบล็อกที่ตัดน้อย

## 5. e หลุมขนาดใหญ่ ⇒ d เล็ก

ลงชื่อเข้าใช้: `e.bit_length() ≈ n.bit_length()` ⟹ d ถูกสร้างขึ้นก่อน (เลือก d ขนาดเล็กแล้วคำนวณ e = d⁻¹ mod φ).

### 5.1 เวียนนา (d < N^0.25/3)

อินเทอร์แฟรกชันของ e/N ให้การลู่เข้า (k, d); สำหรับการลู่เข้าแต่ละครั้ง ให้คำนวณ φ = (e·d − 1)/k, แก้ p+q = n − φ + 1, ตรวจสอบ Δ = (p+q)² − 4n คือสี่เหลี่ยมจัตุรัส เครื่องมือ: `pip install owiener; owiener.attack(e, n)` ตรรกะที่เขียนเอง: `rsalib.wiener_attack` (`rsa/challenge/_lib/`)

### 5.2 โบเนห์–เดอร์ฟี (d < N^0.292)

Wiener ล้มเหลวแต่ e ยังคง ~ bit(n) ⟹ ลอง Boneh–Durfee (ตัวแปร Coppersmith 2: x(A+y)+1 mod e พร้อมด้วย A = N+1) แก้โมเดลการทำงาน: `lattice/L11_boneh_durfee/`; หรือ `crypto-attacks/shared/boneh_durfee.py` ช้ากว่า Wiener มาก (ต้องการ LLL หลายครั้ง)

### 5.3 d_p ขนาดเล็ก (~ 20 บิต)

สัญญาณ: `e = pow(dp, -1, p-1)` ในแหล่งที่มา ⟹ e ~ bit(n)/2 เดรัจฉาน dp:
```python
for dp in range(1, 2**20):
    r = 2
    if 1 < gcd(r - pow(pow(r, e, n), dp, n), n) < n:   # =หน้า
```
แม่นยำยิ่งขึ้น: ตรวจสอบ `pow(2, e·dp, p) == 2` ด้วยตัวเลือกที่ได้รับ p

## 6. โมดูลัสเดียวกัน N

- **No d** (2 ไซเฟอร์เท็กซ์, gcd(e1,e2)=1): อยู่ระหว่าง a·e1 + b·e2 = 1 ⟹ m = c1^a · c2^b ม็อด
```python
a, b = xgcd(e1, e2)[:2]
assert a*e1 + b*e2 == 1                  # อย่างไรก็ตาม จริงอยู่ ค่าสัมประสิทธิ์ลบก็ใช้ได้
m = pow(c1, a, n) * pow(c2, b, n) % n    # py3.8+: pow เอ็กซ์โปเนนเชียลลบใช้การผกผัน (ต้องการ gcd(c,n)=1)
```
**Classic trap**: การใช้ `pow(e1,-1,e2)` และ `pow(e2,-1,e1)` รวมกันเพื่อสร้าง m^(1+e1·e2) — ไม่ใช่ m. ต้องใช้เบซูต์จริง (ความเท่าเทียมกันที่แน่นอน = 1 รวมถึงค่าสัมประสิทธิ์ลบด้วย)
- **มีค่า d ของคู่ตนเองแล้ว**: กรณีนี้โจมตีได้ง่ายกว่ามาก —
  -  วิธีที่ 1 (อนุมาน φ): k = (e·d − 1)//n ค่อยๆ เพิ่มจนกระทั่ง (e·d−1) หารด้วย k และ φ = (e·d−1)/k สำหรับ Δ = (n − φ + 1)² − สี่เหลี่ยม 4n → p, q.
  -  วิธีที่ 2 (ปัจจัยความน่าจะเป็น ทั่วไปสำหรับโครงสร้าง N ทั้งหมด): เขียน e·d − 1 = 2^s·t; เลือก g แบบสุ่ม x = g^t, ยกกำลังสองอย่างต่อเนื่องจนกระทั่งพบ 1; gcd(x − 1, n) ในขั้นตอนก่อนหน้าจะให้ปัจจัยที่ไม่สำคัญ
- หลังจากมี φ: แล้ว "เพื่อน" ทุกคนจะใช้ N เดียวกันกับ e_i → ถอดรหัสด้วย `d_i = pow(e_i, -1, phi)` หากคุณเข้ารหัส **ตามลำดับผ่านหลายเลเยอร์** (m^(e1·e2·…)), จะถอดรหัสใน **ลำดับย้อนกลับ** และอัปเดต c ทุกรอบ

## 7. จดหมายข่าวที่เกี่ยวข้อง

- **Franklin–Reiter** (เข้ารหัส N เดียวกัน e เดียวกัน ความสัมพันธ์เชิงเส้นที่รู้จัก m2 = a·m1 + b): พหุนาม gcd ใน Z_n[x] ของ f1(x) = (x)^e − c1 และ f2(x) = (a·x+b)^e − c2 เท่ากับ (x − m1) การใช้งาน: ขยาย (a·x+b)^e ด้วย **ทฤษฎีบททวินาม** (C(e,k)·a^k·b^(e−k)), mod พหุนามแบบยุคลิด n (การทำให้เป็นมาตรฐานแบบมอนิกโดยการผกผันของสัมประสิทธิ์นำหน้า; ค่าผกผันไม่มีอยู่ ⟹ แยกตัวประกอบ N ตรงนั้น) แก้โมเดล: `rsa/challenge/13_franklin_reiter/`
- **แผ่นสั้น** (m ±แผ่นสั้นเดียวกัน e=3, ไม่ทราบยี่ห้อแผ่น): ผลลัพธ์ของ x³ − c1 และ (x+y)³ − c2 เป็น x สำหรับพหุนามใน y = r2 − r1 → ค้นหา y (Coppersmith small_roots) → กลับไปที่ Franklin–Reiter
- **Coppersmith บิตสูงของ p** (รู้ ≥ n/4 บิตสูง): `p = p_high·2^u + x`, ค้นหา x โดยใช้ `small_roots` (sage):
  ```python
  R.<x> = PolynomialRing(Zmod(n))
  f = p_high*2^u + x
  roots = f.small_roots(X=2^u, beta=0.4)   # X = จุดตัดบนของ x
  ```

## 8. ออราเคิลและลายเซ็น

- **เซิร์ฟเวอร์การลงนาม = ถอดรหัสออราเคิล**: การลงนามในตำราเรียน RSA = m^d — ส่ง **ข้อความเข้ารหัสคีย์ของความลับ** ไปยังการลงนามจุดสิ้นสุดและรับข้อความธรรมดากลับ ด้วยเหตุนี้จึงต้องแฮชลายเซ็นจริงก่อน
- **ปกปิด**: (r^e·m)^d = r·m^d ⟹ คัดลอกสำเนาปก m·r แล้วคูณ r⁻¹. ทั้งการโจมตี (ข้ามตัวกรองเนื้อหา) และเทคนิคการป้องกันเทียบกับจังหวะเวลา r เป็นแบบสุ่ม ไพรม์ร่วมกับ n
- **Parity oracle** (เซิร์ฟเวอร์ส่งคืนเลขคี่/คู่ของ pow(c, d, n)): ส่ง c·(2^k)^e → m·2^k mod n; พาริตีบิต = บิตสูงสุดของ m → การค้นหาแบบไบนารี m ทั้งหมดหลังจากการสืบค้น log₂(n)
- **Bleichenbacher BB'98** (oracle สอดคล้องกับ PKCS#1 v1.5, 2 ไบต์แรก = 00 02): สแกน s เพื่อให้ c·s^e สอดคล้องกับ [2B, 3B) ทำให้ช่องว่างที่มี m แคบลง ตัวอย่างการใช้งาน + รายละเอียดการแก้ไข: `lattice/L12_bleichen_lattice/` และ `rsa/challenge/14_bleichenbacher_pkcs1/`
- **โมดูลัสที่เลือก, e = 1**: ตรวจสอบตัวเองว่าเลือก N, e ⟹ เลือก e=1, N = SIGNATURE − แยกย่อยเพื่อให้ `sig mod N == digest` จำเป็นต้องสร้างการเข้ารหัส EMSA-PKCS1-v1.5 อย่างถูกต้อง (บล็อก 256 ไบต์)
- **โมดูลัสที่เลือกเรียบ + dlog**: N = p^k ด้วย p เล็ก (เช่น 41^144) → กลุ่มตัวคูณราบรื่น → Pohlig–Hellman (พร้อม Hensel lift สำหรับชิ้นส่วน p^(k−1)) คำนวณ **e ดังนั้น** sig^e == แยกย่อยด้วยไดเจสต์ ⟹ "ลายเซ็น" ที่ถูกต้องสำหรับข้อความทั้งหมด ต้องการ sig เป็นตัวสร้าง (ตรวจสอบ `pow(g, 20, P) != 1` และ `pow(g, 8, P) != 1` สำหรับ P=41; หรือเชื่อมต่อใหม่เพื่อรับ sig อื่น)
- **E-root mod 2^k** (unpadding "cut after byte 00"): ตรวจสอบดูเฉพาะค่า mod 256^len — ด้วย e คี่, e-th power จะเป็น bijective บน mod กลุ่มคี่ 2^k ⟹ แก้ x^e ≡ target (mod 2^k) โดย Sage `Mod(target, 256**15).nth_root(3)` — ไม่ d, ไม่ใช่ N
- **CRT error** (ลายเซ็นผิด 1 รายการ): gcd(ŝ^e − m, n) = p พร้อมลายเซ็นผิดพลาด (Bellcore) เรียกดูบันทึกของคู่ (m_i, s_i)
- **ระยะเวลา (Kocher)**: T_i สัมพันธ์กับต้นทุนการคูณระดับบิตของ d — การถดถอยแบบบิตต่อบิตจาก LSB
- **การเปิดรับคีย์บางส่วน (BDF)**: รู้ ≥ ⌈n/4⌉ บิตต่ำของ d → แก้ mod สมการกำลังสอง 2^s รวบรวม mod 2^s → Coppersmith บิตต่ำ `rsa/challenge/17_bdf_partial_key_exposure/`.

## 9. การแพดดิ้งในทางปฏิบัติ

- **OAEP** (PKCS#1 v2): ถอดรหัสด้วย `PKCS1_OAEP.new(key).decrypt(ct)` — อย่าใช้ pow โดยตรง
- **PKCS#1 v1.5 decrypt**: pow เสร็จสิ้นการตัดชิ้นส่วนหลังจาก 0x00 ไบต์แรก
- **การเข้ารหัส EMSA-PKCS1-v1.5** (เมื่อคุณต้องการสร้างบล็อกการตรวจสอบด้วยตนเอง): `00 01 FF..FF 00 || HashInfo || H(msg)` ความยาวเต็มบล็อก
- RSA.construct ต้องการ **pure python int** — ผลลัพธ์ gmpy2 mpz ต้องเป็น `int()` อีกครั้ง
- `Crypto.Util.number.inverse` ตามเวอร์ชัน pycryptodome: ≤3.16 ส่งคืน 0 เมื่อไม่สามารถย้อนกลับได้ (หุบปาก!), 3.17–3.21 เพิ่ม, ≥3.22 ปรับ ในสภาพแวดล้อมที่แปลกประหลาด โปรดใช้ `pow(x, -1, m)` (py3.8+)

## 10. Gotchas รวบรวม

- Sage: `^` คือ **เอ็กซ์โพเนนเชียล** (ตัวเตรียมวิเคราะห์), `^^` คือ XOR — ตรงกันข้ามกับ Python โดยสิ้นเชิง
- `gmpy2.iroot` ส่งคืนทูเพิล (รูท, แฟล็กที่แน่นอน) - การลืมตรวจสอบแฟล็กหมายถึงการได้รับรูทที่แน่นอน
- การดำเนินการทั้งหมด "gcd(x^e − c_i, y^e − c_j)" ประเภทข้อความธรรมดาที่รู้จัก RSA: เรียกใช้ gcd ในหลายคู่ ปัจจัยร่วม t·n สามารถรวมปัจจัย t ได้ — การแบ่งการทดลอง
- CRT ต้องใช้โมดูลัส **ไพรม์รวมกันเป็นคู่** — หากพบคู่ที่ไม่ใช่โคไพรม์ gcd นั้นเป็นปัจจัย (โจมตีเสมอ)
- `long_to_bytes` การสูญเสียศูนย์นำหน้า — เมื่อจำเป็นต้องใช้ความยาวคงที่ `rjust(n, b'\0')`
- Wiener ล้มเหลว ⟹ อย่าเพิ่มจำนวนการบรรจบกันอย่างไม่สิ้นสุด เปลี่ยนเป็น Boneh–Durfee หรือตรวจสอบสาขา d_p เล็ก ๆ (ดูที่ความยาวบิตของ e เพื่อเลือก)
- หลังการแยกตัวประกอบด้วยวิธีใดก็ตาม: `assert p*q == n` ทุกครั้งก่อนคำนวณ d
