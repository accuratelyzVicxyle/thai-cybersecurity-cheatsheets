## 1. AES ภายใน (AES ทำงานอย่างไร 01–07)

เจ็ดบทเรียนแรกเป็นบทเรียนการนำไปปฏิบัติด้วยตนเองสำหรับ AES-128; ค่าถาวรคือ **ตามลำดับการแปลงเพื่ออ่านรหัส AES ที่เสียหาย**

- **State** เป็นเมทริกซ์ขนาด 4×4 ไบต์ โหลดใน **COLUMNS**: `state[r][c] = b[r + 4c]`; อ่านกลับกันเป็น `matrix2bytes`
- AES-128: 10 รอบ; ตารางคีย์สร้าง 44 คำ (11 ปุ่มกลม)
- E แต่ละรอบการเข้ารหัส: `SubBytes → ShiftRows → MixColumns → AddRoundKey(k_i)`; รอบที่แล้ว **ไม่มี MixColumns**
- **ลำดับการถอดรหัสของ 1 บล็อก** (ใช้หลายครั้งเมื่ออ่านโค้ดย้อนกลับ):
  1. `AddRoundKey(k10)`
  2. ทำซ้ำใน = 9 → 1: `InvShiftRows → InvSubBytes → AddRoundKey(k_i) → InvMixColumns`
  3. `InvShiftRows → InvSubBytes → AddRoundKey(k0)`
- InvShiftRows: แถว r หมุน ** ขวา ** ตำแหน่ง r InvMixColumns คูณด้วยเมทริกซ์ `{0e,0b,0d,09}`
- MixColumns เป็นตัวคูณเมทริกซ์ใน mod GF(2⁸) x⁸+x⁴+x³+x+1 (0x11B); การคูณ 1 ไบต์สตริง = `xtime`: `xtime(x) = (x<<1) ^ (0x11B nếu tràn bit 8)`
- 01 · การเรียงสับเปลี่ยนแบบคีย์: บล็อกการเข้ารหัสคือ **การเรียงสับเปลี่ยนด้วยคีย์** — การแมป 16 ไบต์ → 16 ไบต์จะต้องเป็นแบบ bijective เพื่อถอดรหัส
- 02 · การต่อต้าน Bruteforce: การโจมตี AES ดั้งเดิมที่ได้รับการตีพิมพ์ที่ดีที่สุดคือ **การเข้ารหัสแบบ biclique** (เร็วกว่า bruteforce เล็กน้อย แต่ใช้งานไม่ได้จริง)—AES ยังคงปลอดภัยแบบ brute-force
- 03 · โครงสร้างของ AES:.ทำให้เมทริกซ์เรียบขึ้นทีละคอลัมน์ เท่านี้ก็เสร็จเรียบร้อย
- 04 · Round Keys: `AddRoundKey` = XOR state พร้อมคีย์กลม (16 ไบต์)
- 05 · ความสับสนผ่านการทดแทน: `sub_bytes` ใช้ S-box; ถอดรหัส **S-box กลับ ** ไบต์ทีละไบต์
- 06 · การแพร่กระจายผ่านการเรียงสับเปลี่ยน: แรงดันย้อนกลับ `inv_shift_rows` + `inv_mix_columns`
- 07 · Bringing It All Together: รวมทั้งหมด — ใช้กำหนดการคีย์ + รอบการถอดรหัสดังที่กล่าวข้างต้น

Gotchas ทั่วไปเมื่ออ่านโค้ด AES ที่บิดเบี้ยว: การสลับ SubBytes/ShiftRows เป็นลูป การลืม InvMixColumns ในลูปที่ถูกต้อง หรือการโหลดสถานะใน **แถว** แทนที่จะเป็นคอลัมน์ — การถอดรหัสขยะเป็นประจำ เปรียบเทียบแต่ละบรรทัดกับมาตรฐาน FIPS-197

## 2. ตารางโหมด → ข้อบกพร่องทั่วไป

| โหมด | สูตรอาหาร | ข้อบกพร่องทั่วไป |
|---|---|---|
| อีซีบี | C_i = E(P_i) | บล็อกซ้ำรูปแบบการเปิดเผย (เพนกวิน); ออราเคิลทีละไบต์ |
| ซีบีซี | C_i = E(P_i ⊕ C_{i−1}) | ออราเคิลเสริม; bit-flip (แก้ไข C_{i−1} เปลี่ยน P_i, บล็อกก่อนหน้าใช้งานไม่ได้); ปุ่ม IV = |
| ซีเอฟบี | P_i = C_i ⊕ E(C_{i−1}) | สตรีมมิ่ง; CFB8 = ข้อเสนอแนะแบบไบต์ต่อไบต์ → Zerologon |
| โอเอฟบี | ks_i = E(ks_{i−1}), ks_0 = E(IV) | ks_i ปุ่ม IV = ⇒ เข้ารหัส ถอดรหัส = |
| ซีทีอาร์ | ks_i = E(nonce ∥ counter_i) | ไม่ใช้ซ้ำ ⇒ การใช้คีย์สตรีมซ้ำ (MTP) |
| จีซีเอ็ม | CTR + แท็ก GHASH | ไม่ใช้ซ้ำ ⇒ การโจมตีที่ต้องห้าม (เปิดเผย H, ปลอมแท็ก) |
| ไอจีอี | P_i = D(C_i) ⊕ P_{i−1} ⊕ C_{i−1} | ตัวแปรเสริมของ oracle (สไตล์โทรเลข) |

กฎทั่วไป: **โหมดเป็นเพียงวิธีการห่อหุ้มรหัสบล็อก** จุดบกพร่องทั้งหมดแบ่งออกเป็น 1 ใน 3 กลุ่ม: (a) คีย์สตรีมซ้ำ (OFB/CTR/GCM nonce), (b) oracle ให้คุณเลือกอินพุตของ E หรือ D (ECB/CBC), (c) การตรวจสอบสิทธิ์ที่อ่อนแอ (แท็ก GCM ที่มี nonce ซ้ำ)

## 3. 29 บทเรียน — รายละเอียดสำหรับแต่ละบทเรียน

### 3.1 AES ทำงานอย่างไร (01–07)

ดูหัวข้อที่ 1 ห้ามโจมตี เป้าหมายคือการเรียนรู้ระบบภายในให้เชี่ยวชาญ เพื่อว่าในบทเรียนต่อไปนี้ คุณสามารถอ่านโค้ดและรู้ว่ามีอะไรผิดปกติเกิดขึ้นบ้าง

### 3.2 สตาร์ทแบบสมมาตร (08–09)

**08 โหมด · ของ Operation Starter (15)** — เรียก API `encrypt_flag` เพื่อรับ `{ciphertext, iv}` จากนั้นเรียก `decrypt` เพื่อส่งคืนคีย์/ct มาทำความรู้จักกับ JSON + hex กันดีกว่า Gotcha: ถอดรหัสฐานสิบหกก่อน `unpad`

**09 · รหัสผ่านเป็นคีย์ (50)** — คีย์ = `MD5(word).digest()` พร้อมด้วย `word` ในรายการคำที่กำหนด

```python
for word in WORDLIST:
    key = MD5(word.encode()).digest()
    try:
        pt = AES.new(key, AES.MODE_ECB).decrypt(ct)
        if pt.startswith(b"crypto{"): print(pt)   # ตรวจสอบคำนำหน้าแทน unpad
    except Exception: pass
```

Gotcha: หลังจากถอดรหัส `unpad` แล้ว อาจมีข้อยกเว้นเกิดขึ้นเนื่องจากการเติมขยะ — การตรวจสอบด้วยแฟล็กคำนำหน้าจะสะอาดยิ่งขึ้น

### 3.3 รหัสบล็อก 1 (10–14)

**10 · ECB CBC WTF (55)** — เซิร์ฟเวอร์เข้ารหัสด้วย CBC แต่การถอดรหัสจุดสิ้นสุดจะบล็อก ECB ทีละบล็อกเท่านั้น (ลืม XOR) XOR ตัวคุณเองทางฝั่งไคลเอ็นต์:

```python
prev = iv
for i in range(0, len(ct), 16):
    pt_block = xor(dec_ecb(ct[i:i+16]), prev)
    prev = ct[i:i+16]
```

**11 · ECB Oracle (60)** — เซิร์ฟเวอร์เข้ารหัส `input || FLAG` โดยใช้ ECB เนื่องจาก ECB กำหนดไว้ บล็อกอินพุตเดียวกัน → บล็อกเอาต์พุตเดียวกัน

```python
def attack(oracle, N=16):
    flag = b""
    while True:
        p = N - 1 - len(flag) % N
        idx = (len(p*"A") + len(flag) + 1) // N      # บล็อกมีไบต์ที่ไม่รู้จัก
        target = oracle(b"A"*p)[:idx*N]
        for c in range(256):
            if oracle(b"A"*p + flag + bytes([c]))[:idx*N] == target:
                flag += bytes([c]); break
        else:
            return flag
```

แนวคิด: วางอินพุตเพื่อให้ **ไบต์สุดท้ายของแฟล็กตกที่ส่วนท้ายของบล็อก**; บล็อกนั้นเข้ารหัส `A*…A + flag_known + x` - ค่า brute 256 x บล็อกที่ตรงกันคือไบต์ที่ถูกต้อง Gotcha: เมื่อแฟล็กยาวกว่า 1 บล็อก `idx` จะต้องเพิ่มขึ้นอย่างเหมาะสม การใช้ dict `{block: byte}` เพื่อสร้างจากการสืบค้นก่อนหน้านี้จะเร็วขึ้นมาก

**12 · Flipping Cookie (60)** — คุกกี้ `admin=False;…` เข้ารหัส CBC เซิร์ฟเวอร์จะตรวจสอบเฉพาะข้อความธรรมดาเท่านั้น

```python
iv = bytearray(iv)
i = cookie.find(b"False")
iv[i:i+5] = xor(iv[i:i+5], xor(b"False", b"True;"))   # เท็จ → จริง;
```

แก้ไขบล็อกข้อความธรรมดา 0 ⟹ แก้ไข **IV** ที่ตำแหน่งเดียวกัน แก้ไขบล็อก i (i>0) ⟹ แก้ไขบล็อกข้อความเข้ารหัส i−1 และ **ยอมรับบล็อกข้อความธรรมดาที่เสียหาย i−1**. Gotcha: คงความยาวของสตริงทดแทนไว้ไม่เปลี่ยนแปลง (`False`→`True;`) เพื่อให้ส่วนต่อไปนี้ไม่สอดคล้องกัน

**13 · ขี้เกียจ CBC (60)** — `iv = KEY`. ส่ง `ct = C0 || 00*16 || C0`:

- P0 = D(C0) คีย์ ⊕
- P2 = D(C0) ⊕ 0

⟹ `key = P0 ⊕ P2`. เซิร์ฟเวอร์ส่งคืนข้อความธรรมดา (ผ่านข้อความแสดงข้อผิดพลาดของปลายทางที่ได้รับข้อมูล) — อ่านเลขฐานสิบหกเพื่อรับคีย์ ถอดรหัสแฟล็ก

**14 · Triple DES (60)** — เลือก **คีย์** สำหรับ DES3 4 ปุ่มที่อ่อนแอ:

```
0101010101010101  FEFEFEFEFEFEFEFE  E0E0E0E0F1F1F1F1  1F1F1F1F0E0E0E0E
```

ด้วยคีย์อ่อน `E(E(x)) = x` (E อยู่ตรงข้าม) 3DES(K1,K2,K1) = E1∘D2∘E1; เมื่อทั้งสองอ่อนแอ **ใช้สตริงสองครั้ง = identity** ⟹ "เข้ารหัส" ไซเฟอร์เท็กซ์อีกครั้งเพื่อส่งคืนข้อความธรรมดา Gotcha: DES3 ต้องการคีย์ 16 ไบต์ในรูปแบบ `K1 || K2` (K1 นำมาใช้ซ้ำสำหรับตำแหน่ง 3)

### 3.4 รหัสสตรีม (15–21)

**15 · สมมาตร (50)** — OFB พร้อม `iv = KEY` OFB เพียง XORs ข้อความธรรมดาพร้อม keystream ⟹ **การเข้ารหัสคือถอดรหัส** การส่งไซเฟอร์เท็กซ์ไปยังปลายทางการเข้ารหัสจะได้รับแฟล็กกลับมา

**16 · Bean Counter (60)** — รูปภาพ PNG ที่เข้ารหัส CTR แบบโฮมเมดพร้อมตัวนับรีเซ็ต ⟹ สตรีมคีย์แบบวน 16 ไบต์

```python
hdr = bytes.fromhex("89504e470d0a1a0a0000000d49484452")   # เวทย์มนตร์ PNG + IHDR
ks = xor(ct[:16], hdr)
pt = xor(ct, (ks * (len(ct)//16 + 1))[:len(ct)])
```

Gotcha: ข้อความธรรมดาคือรูปภาพ — หลังจากแก้ไขแล้ว ให้บันทึกเป็นไฟล์ จากนั้น **เปิดรูปภาพแล้วดู** อย่าดูที่เลขฐานสิบหก

**17 · CTRIME (70)** — ข้อความธรรมดาคือ `zlib.compress` ก่อนการเข้ารหัสด้วย CTR ⟹ **ความยาวของข้อความเข้ารหัสคือ oracle** (CRIME/BREACH กลุ่มเดียวกัน)

```python
flag = "crypto{"
while not flag.endswith("}"):
    base = len(enc(flag))
    for c in string.printable:
        if len(enc(flag + c)) <= base:    # การบีบอัดที่ดีขึ้น = เดาถูก
            flag += c; break
```

แนวคิด: การเดาอักขระตัวถัดไปอย่างถูกต้องทำให้เนื้อหาที่บีบอัดมีขนาดเล็กลงกว่า ⟹ ct สั้นลงหรือคงเดิม ถ้าทายผิดมันจะบวม Gotcha: การส่ง `guess + c` วนซ้ำสองครั้งทำให้เอฟเฟกต์การบีบอัดชัดเจนยิ่งขึ้น ลองสั่ง `string.printable` ดูครับ

**18 · Logon Zero (80)** — CFB8 + รีเซ็ตรหัสผ่านตามโทเค็นที่คุณส่ง (บริบท Netlogon / Zerologon CVE-2020-1472)

CFB8: `pt[i] = AES(state)[0] ^ ct[i]`, `state = state[1:] + ct[i]` — IV อยู่ใน ** ไซเฟอร์เท็กซ์ที่ฉันส่ง ส่งโทเค็นทั้งหมด `00` × 29: state ≡ 0 ⟹ `pt = E(0)[0]` ทำซ้ำทั้งหมด 29 ไบต์ ความน่าจะเป็น 1/256 ต่อคีย์: `E(0)[0] = 0` ⟹ 4 ไบต์สุดท้าย (password_length) = 0 ⟹ รหัสผ่านว่างเปล่า ⟹ เข้าสู่ระบบด้วยสตริงว่าง หากล้มเหลว ให้รีเซ็ตการเชื่อมต่อ (รหัสใหม่) แล้วลองอีกครั้ง ~256 ครั้ง นี่คือช่องโหว่ "คีย์เซสชันที่ไม่ได้รับการรับรองความถูกต้อง" ของ Netlogon Secure Channel

**19 · กระแสแห่งจิตสำนึก (80)** — สตรีมคีย์แบบคงที่; เซิร์ฟเวอร์พูดประโยคจากรายการเนื้อเพลงที่รู้จัก เข้ารหัสแฟล็กและคีย์สตรีม

วิธีแก้: ลองทีละประโยค `s`: `ks = xor(ct_song, s)` → `flag = xor(ct_flag, ks)` แล้วตรวจ prefix `crypto{` กับดักสำคัญ: ถ้าสองประโยคมี prefix เหมือนกัน การ XOR ciphertext สองชุดในช่วง prefix จะได้ศูนย์ ทำให้ **crib ถูก echo กลับมา** และเกิด false positive `crypto{` ต้องตรวจ flag ทั้งหมดว่าจบด้วย `}` ถูกต้อง หรือให้ความสำคัญกับประโยคที่ยาว/ไม่ซ้ำกัน

**20 · Dancing Queen (120)** — การใช้งาน ChaCha20 ด้วยตนเอง **ขาดการป้อนไปข้างหน้า** (ไม่ได้เพิ่มสถานะเริ่มต้นที่ส่วนท้าย)

ฟังก์ชั่นบล็อกมาตรฐานเมื่อสิ้นสุดรอบจะเพิ่มสถานะดั้งเดิม ไม่มีขั้นตอนนี้ ⟹ สตริงรอบควอเตอร์แท้ **กลับด้านได้** ข้อความธรรมดาที่รู้จักได้รับบล็อกสตรีมคีย์ → ย้อนกลับแต่ละการดำเนินการ (`+`→`−` mod 2³², `<<<r`→`>>>r`, ย้อนกลับ XOR ด้วยตนเอง, ** กลับลำดับของการดำเนินการในรอบควอเตอร์ **) ไปสู่สถานะดั้งเดิม → ** คีย์ สถานะ =[4:12]** (เค้าโครงสถานะ: 4 ค่าคงที่ + 8 คีย์ + ตัวนับ + nonce) แก้โมเดล: `Cryptohack/Dancing Queen/solve.py`

### 3.5 การโจมตีเสริม (22–26)

**22 · PAD THAI (80)** — padding oracle ของ CBC แบบคลาสสิก (Vaudenay 2002) ส่ง `(fake_prev_block, cur_block)` → True/False ตามว่า PKCS7 ถูกต้องหรือไม่

```python
def dec_block(query, prev, cur, HEX=False):
    D = bytearray(16)
    for i in range(15, -1, -1):
        pv = 16 - i                                  # การเติมมูลค่าเพื่อสร้าง
        for g in (b"0123456789abcdef" if HEX else range(256)):
            fake = bytearray(prev)
            for j in range(i+1, 16):
                fake[j] = prev[j] ^ D[j] ^ pv
            fake[i] = prev[i] ^ g ^ pv
            if query(bytes(fake), cur):
                if i > 0:                            # ฆ่า n>=2: ผลบวกลวง
                    fake[i-1] ^= 1                   # พลิกบิต สอบถามอีกครั้งและยังคงได้รับ True
                    if not query(bytes(fake), cur): continue
                D[i] = g; break
    return bytes(D)                                    # ข้อความธรรมดา = D ^ prev_true
```

แนวคิด: ถอดรหัสแต่ละบล็อกโดย **สร้างบล็อกก่อนหน้าของคุณเอง** เพื่อให้ช่องว่างภายในนั้นถูกต้อง จากไบต์สุดท้าย (ช่องว่างภายใน 1) ถอยหลัง แต่ละไบต์ที่รู้จักจะถูก "ตรึง" ไว้ในบล็อกปลอมสำหรับขั้นตอนต่อไป Gotcha ของบทความนี้: เซิร์ฟเวอร์ได้รับเพย์โหลดเท่านั้น ** 2 บล็อกอย่างแน่นอน ** (นานกว่านั้นจะยกเลิกการเชื่อมต่อ) และการตรวจสอบอย่างไม่ถูกต้องจะส่งคืนข้อผิดพลาดเท่านั้น แต่ไม่ทำลายการเชื่อมต่อ ⟹ การสืบค้นไปป์ไลน์สามารถแบทช์ได้ ข้อความธรรมดาฐานสิบหก ⟹ เพียง 16 ตัวผู้สมัคร/ไบต์ แทนที่จะเป็น 256

**23 · Rhetorical Oracle (100)** — เปิดตัวเมื่อเดือนตุลาคม 2569 **ยังไม่มีการเขียนต่อสาธารณะ** (ตุลาคม 2569) แบบฟอร์ม "โน้มน้าวผู้ดูแลระบบ": การพลิกตัวแปรคุกกี้เมื่อ oracle ตอบสนองด้วยการจัดการข้อผิดพลาด คำแนะนำที่ควรลอง: อ่านการตอบสนองทั้งหมดอย่างละเอียด (รวมถึงข้อผิดพลาด) เพื่อค้นหาช่องทางการรั่วไหล ลองใช้ bit-flip IV ในหลาย ๆ ตำแหน่ง ดูว่าคำนำหน้า/คำต่อท้ายใดที่เซิร์ฟเวอร์ตรวจสอบ หลังจากแก้ไขปัญหาแล้ว ให้จดลงในตารางในแผนผังการระบุตัวตน

**24 · The Good, The Pad, The Ugly (100)** — padding oracle **noise หรือ**: `good | (rng.random() > 0.4)`

- Noise `rng() > 0.4`=จริง โดยมีความน่าจะเป็น 0.6 และ หรือ รู้เพียงว่าต้องเพิ่ม 0→1 ⟹ คำตอบ **เท็จ ถูกต้องเสมอ** จริง ถือเป็นที่น่าสงสัย
- Each กด True **ยืนยันอีกครั้ง ×23** (0.6²³ ≈ 10⁻⁵ — ข้อผิดพลาดที่ยอมรับได้) งบ 12000 สอบถามครับ
- Plaintext hex ⟹ 16 ตัวเลือก/ไบต์ ก็เพียงพอแล้ว

**25 · Oracular Spectacular (150)** — สัญญาณรบกวน **XOR**: `good ^ (rng.random() > 0.4)` — ไม่เชื่อคำตอบใดๆ เลย (แต่ละคำตอบถูกต้อง 60%)

กลยุทธ์ทางสถิติ:
- E ผู้สมัครแต่ละคนมอบหมาย n แบบสอบถาม; นับ t คูณ True; **LLR = t·ln(0.4/0.6) + (n−t)·ln(0.6/0.4)** — ตัวเลือกที่ถูกต้องซึ่ง LLR เพิ่มขึ้นเชิงเส้นด้วย n
-  เน้นคำถามไปที่ผู้สมัคร **2 อันดับแรก** อย่ากำจัดพวกเขาอย่างถาวร (ผู้สมัครที่ไม่ดีอาจเป็นเพียงโชคร้าย)
-  ความน่าจะเป็นต่ำที่จะประสบความสำเร็จต่อการรัน → **เชื่อมต่อใหม่และทำซ้ำ** เป็นกลยุทธ์หลัก ไม่ใช่พยายามเชื่อมต่อ

**26 · Rhetorical Oracle 2 (150)** — ส่วนที่ 2 จาก 23 สถานะเดียวกัน **TBD** (ยังไม่มีการเขียนต่อสาธารณะในเดือนตุลาคม 2569) ทิศทางเดียวกันของการสอบสวน: ความแตกต่างระหว่างสาขาข้อผิดพลาดของ Oracle

### 3.6 การเข้ารหัสรับรองความถูกต้อง (27–28)

**27 · Paper Plane (120)** — โหมด **IGE** (ใช้โดย Telegram): `M_i = D(C_i) ⊕ C_{i−1} ⊕ M_{i−1}` พร้อมบล็อกเริ่มต้น 2 บล็อก (m0, c0) สาธารณะ

Oracle Padding เป็นมาตรฐาน แต่บล็อกถัดไปถูกโยงตาม **ข้อความธรรมดาของบล็อกก่อนหน้า** ⟹ แก้ไขแล้วในลำดับพิเศษ: ตัดบล็อกสุดท้ายด้วย `(c0', m0')` ที่คุณเลือกก่อน หลังจากแก้ไขบล็อกถัดไปแล้ว ให้ใช้ข้อความธรรมดาที่เพิ่งแก้ไขเป็น `m0` สำหรับบล็อกก่อนหน้า ข้อผิดพลาด "ไม่สามารถถอดรหัส" = oracle bit

**28 · ผลไม้ต้องห้าม (150)** — GCM ไม่ใช้ซ้ำสำหรับข้อความธรรมดาเข้ารหัส 2 รายการที่คุณเลือก

nonce เดียวกัน ไม่มี AAD 1 บล็อก: `tag = c·H² + X` (H = E(0), X ขึ้นอยู่กับความยาว) ⟹

- `H² = (t1 − t2)·(c1 − c2)⁻¹` ใน GF(2¹²⁸)
- `X = t1 − c1·H²`

เข้ารหัสข้อความธรรมดาที่จะส่ง ปลอมแปลง `tag' = c₃·H² + X` GCM ของฟิลด์: พหุนาม `x¹²⁸ + x⁷ + x² + x + 1`, **บิตย้อนกลับแต่ละไบต์** เมื่อเปลี่ยนไบต์ ↔ องค์ประกอบฟิลด์ (แบบแผนที่สะท้อน) ปราชญ์:

```python
R.<x> = GF(2)[]; F = R.quotient(x^128 + x^7 + x^2 + x + 1)

# เท่ากับคู่ (c, t) ที่ถูกเข้ารหัสด้วยตนเองก่อนที่จะเชื่อถือผลลัพธ์
```

### 3.7 การเข้ารหัสเชิงเส้น (29)

**29 · Beatboxer (150)** — การเข้ารหัสแบบ AES แต่เป็น S-box ที่แปลกประหลาด ทดสอบ 1 บรรทัด:

```python
all(sbox[a^b] == sbox[a]^sbox[b]^sbox[0] for a in range(256) for b in range(256))
```

หากเป็นจริง: S-box affine ⟹ **การจับคู่การเข้ารหัสทั้งสองแบบกับความสัมพันธ์** `E(x) = M·x ⊕ c` บน GF(2)¹²⁸ โดยที่ **M เป็นคีย์ที่ไม่ขึ้นต่อกัน** (คีย์เพียงแปลงค่าคงที่ c ผ่าน AddRoundKey; SubBytes/ShiftRows/MixColumns ทั้งหมดเป็นแบบเชิงเส้นเชิงเส้น)

```python
E = cipher_with(bat_ky_key); c0 = E(b"\0"*16)
cols = [xor(E(e_j), c0) for j in range(128)]     # e_j = บล็อกบิตที่ถูกต้อง j = 1

# 1 เซิร์ฟเวอร์แบบสอบถาม encrypt(block 0) → c_server (ซึ่งเป็นค่าคงที่ c ของเซิร์ฟเวอร์)
# flag_block = M^{-1}·(ct_block ⊕ c_เซิร์ฟเวอร์)
```

## 5. เทคนิคออราเคิลเสียงและความเร่ง

- **OR-noise** (`good | rand>0.4`): เท็จคือการพิสูจน์ True จำเป็นต้องมีการยืนยันหลายครั้ง จำนวนการยืนยันที่เลือกตามงบประมาณ: 0.6ⁿ < ข้อผิดพลาดในการยอมรับ ⟹ n = 23 สำหรับ 10⁻⁵.
-  **XOR-noise** (`good ^ rand>0.4`): สัญญาณทั้งหมดมีเสียงรบกวน ⟹ LLR สะสม มุ่งทรัพยากรไปที่ 2 อันดับแรก และถือว่า **การรันแต่ละครั้งเป็นการทดสอบ Bernoulli** — การเชื่อมต่อใหม่เป็นสาขาหนึ่งของอัลกอริทึม
- **การสืบค้นไปป์ไลน์**: รวบรวมการสืบค้น 32–256 ครั้งในคราวเดียว (บัฟเฟอร์ pty ของเซิร์ฟเวอร์ขนาดเล็กลดขนาดแบตช์) ประสบการณ์การต่อสู้จริง: 16.4k คำขอ / 176 วินาทีพร้อม 24 เธรด
- Oการเชื่อมต่อที่ไม่ทำงานเมื่อไม่ถูกต้อง: ใช้การเชื่อมต่อแบบ end-to-end 1 ครั้งสำหรับแต่ละบล็อก เชื่อมต่อใหม่ระหว่างบล็อก
-  จัดลำดับความสำคัญของการลดช่องว่างของผู้สมัครก่อนเดรัจฉาน: ข้อความธรรมดาฐานสิบหก (16), พิมพ์ได้ (~95), ตัวอักษรและตัวเลขเท่านั้น (62)
