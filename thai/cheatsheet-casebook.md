# Casebook — สมุดบันทึกกรณีศึกษา

รวบรวมรูปแบบโจทย์ที่อยู่นอกสองหมวดหลัก (symmetric cipher ล้วนและ RSA ล้วน): encoding แปลกๆ, cipher ทำเอง, forensics/stego หลายชั้น และ RE เบาๆ แต่ละเคสเขียนตามรูปแบบ **วิธีสังเกต → วิธีแก้ → กับดัก** เพื่อให้เห็นลักษณะคล้ายกันแล้วนึกถึงแนวทางได้ทันที

กฎทั่วไปเมื่อประสบปัญหาไฮบริด (crypto + forensics + RE): **ระบุเลเยอร์นอกสุดก่อน ลอกแต่ละเลเยอร์ออกทีละเลเยอร์ โดยใช้เครื่องมือพิเศษที่เหมาะสมสำหรับแต่ละเลเยอร์** — อย่าพยายามเขียนสคริปต์ทั้งหมดตั้งแต่ต้น

## 1. การเข้ารหัสและการเข้ารหัสแบบคลาสสิก

### 1.1 Base64 — อักขระไม่สามารถปรากฏได้

- **การระบุ:** คำถามประเภท "อักขระ base64 ใดที่ไม่เคยปรากฏในเอาต์พุต" (โดยมีชุดอินพุตที่จำกัด เช่น แค่ตัวอักษร)
-  **วิธีแก้ปัญหา:** Base64 รวบรวม 3 ไบต์ → 4 อักขระ ด้วยอินพุตที่ประกอบด้วยเพียง A–Z/a–z (ไบต์จะเริ่มต้น `01…` เสมอ) ซึ่งลัดเลาะไปตามลำดับ A-Za-z ทั้งหมดที่มีความยาว 1–3 (52 + 52² + 52³ ≈ 143,000) ครอบคลุมตำแหน่งเอาต์พุตที่เป็นไปได้ทั้งหมด ส่วนเสริมของชุดที่ปรากฏ (ยกเว้น `=`) คือคำตอบ ตัวอย่างคลาสสิกที่มีการป้อนตัวอักษรล้วนๆ: `+` และ `/` (ดัชนี 62/63 ต้องใช้บิตแรก = 1), `f` (ต้องการไบต์ 0x7C–0x7F), `7` (low6 = 111011 > สูงสุด 111010) → `+/7f` → มักจะถามถึง SHA1 ของสตริงนั้น
- **กับดัก:** อย่าลืมลบ `=`; คำนวณ SHA1 ของสตริง **จัดเรียงตามลำดับ ASCII จากน้อยไปมาก** ในรูปแบบที่ถูกต้อง

### 1.2 โซ่เท่านั้น `.` และ `-` กลุ่ม 5 — Baudot/ITA2

-  **การระบุ:** ข้อความที่เต็มไปด้วย `.`/`-` คำใบ้ "โทรเลข/มอร์ส" แต่ไม่มีตัวคั่นมอร์สและจังหวะที่แบ่งออกเป็นกลุ่ม 5 เท่าๆ กัน → มอร์สเป็นตัวล่อ จริงๆ แล้วเป็นรหัสบล็อก 5 บิต ITA2/Baudot
-  **วิธีแก้ปัญหา:** ตัวกรองจะเก็บเฉพาะ `.`/`-` → กลุ่ม 5 บิต → ลอง 4 รูปแบบ {`.` = 1 หรือ 0} × {กลับบิตในกลุ่มหรือไม่} → ค้นหาตารางตัวอักษร ITA2 เลือกตัวแปรเพื่อให้ได้ข้อความที่สะอาดที่สุด ผลลัพธ์อาจเป็นคำที่สะกดแบบ NATO/สวีเดน (Adam=A, Bertil=B, Caesar=C…) → รวมตัวอักษรตัวแรกของแต่ละคำ เครื่องมือที่ใช้ได้: `classical/baudot.py`
- **กับดัก:** โทเค็นควบคุม LTRS/FIGS ดูเหมือนคำจริง แต่จะต้องลบออกก่อนที่จะรวมตัวอักษรตัวแรก

### 1.3 Vigenère ซ่อนอยู่ในช่องเจาะ

- **การระบุ:** รูปภาพ JPEG + `binwalk` แสดง ZIP ต่อท้าย + ส่วนของรูปภาพหลายส่วนที่ถูกตัดจากรูปภาพเดียวกัน → stego หลายชั้น; ข้อความที่ได้มีรูปแบบ `XXXX_XXXX{...}` อันเป็นเอกลักษณ์ของ Vigenère
-  **วิธีแก้ปัญหา:** `strings` เป็น 1 ชิ้น; **การเรียงลำดับชิ้นส่วนจะต้องประกอบใหม่ทั้งภาพโดยอัตโนมัติ** (ไม่เป็นไปตามชื่อไฟล์) ผนวกลำดับที่ถูกต้องลงในไซเฟอร์เท็กซ์ ถอดรหัสVigenère (ใช้เฉพาะตัวอักษรเท่านั้น รักษาอักขระอื่นให้ครบถ้วน) คีย์สามารถอนุมานได้จากแฟล็กรูปแบบคำนำหน้าเปล =: แปลตัวอักษรเอาต์พุตกะ 3 ตัวต่อกัน → คีย์ซ้ำ
- **กับดัก:** ลำดับของแฟรกเมนต์ไม่ถูกต้อง = ไซเฟอร์เท็กซ์ที่ไม่มีความหมาย คิดว่าไปในทิศทางที่ผิด ZIP มักจะมีรหัสผ่าน (ดูในข้อมูลเมตาของรูปภาพหรือคำใบ้ชื่อ)

### 1.4 ปุ่มVigenère = ทศนิยมของเศษส่วนที่เกิดซ้ำ

- ** การระบุ:** ข้อความธรรมดาภาษาอังกฤษปกติจากนั้นก็ "ใช้งานไม่ได้" เหมือน KeyStream; สตรีมคีย์มีความยาวประมาณ 16+ แต่ซ้ำ ตัวเลขที่ "สวยงาม" ปรากฏในคำใบ้ (เศษส่วนเช่น 1/17)
-  **วิธีแก้ไข:** คีย์ = **รอบทศนิยม** (ซ้ำ) ของเศษส่วนซึ่งมักจะถูกตัดทอน (1/17 = 0.0588235294117647… → รอบ 0588235294117647 เป็นไปได้เพียง 6 หลักซ้ำกัน "058823"). หากทราบรูปแบบเศษส่วน ให้สร้างการทำซ้ำแบบเต็ม จากนั้นจึงตัดความยาวที่ตัดออก
- **กับดัก:** การทำซ้ำทั้งหมดอาจล้มเหลวแม้ในทิศทางที่ถูกต้อง — เธรดถูกตัดทอนแล้ว รูปแบบการตัดที่ดุร้ายเสมอ ปุ่มตัวเลขถูกปิดเสียงโดยชุดเครื่องมือบางตัว → แปลงเป็นข้อความ (ค้นหาตาราง A=0..9=I) หากเครื่องมือต้องการ)

### 1.5 OTP คีย์ฝังตัวเอง

-  **การระบุ:** ไซเฟอร์เท็กซ์ที่ยาวผิดปกติพร้อมด้วยตัวอย่าง (การเข้ารหัส, ข้อความธรรมดา) เพื่อการเปรียบเทียบ → โครงสร้างการฝังคีย์ลงในไซเฟอร์เท็กซ์เอง: `cipher = [base64(pt) ⊕ key] || [key]` ทั้งสองซีกเท่ากัน
-  **วิธีแก้ปัญหา:** XOR ไบต์สองซีก → จับสตริง base64 → ถอดรหัส:
  ```python
  h = len(c) // 2
  b64 = bytes(a ^ b for a, b in zip(c[:h], c[h:]))
  print(base64.b64decode(b64))
  ```
- **กับดัก:** XOR ดำเนินการกับไบต์ของสตริง BASE64 ไม่ใช่ข้อความธรรมดาแบบดิบ ตรวจสอบสูตรบนคู่ตัวอย่างก่อนใช้งานจริง

### 1.6 สตรีมรหัสแบบโฮมเมด `c_i = m_i + 2·m_{i+1}`

- **การระบุ:** การเข้ารหัสแบบโฮมเมดซึ่งแต่ละไบต์ที่เข้ารหัสจะขึ้นอยู่กับไบต์ข้อความธรรมดา 2 ไบต์ติดต่อกัน (เป็นคู่เชิงเส้น)
-  **วิธีแก้ปัญหา:** แก้ **ย้อนกลับจากอักขระที่รู้จักตัวสุดท้าย** (`}` ของแฟล็กรูปแบบ) — แต่ละขั้นตอนมีเพียง 1 วิธีเท่านั้น:
  ```python
  out = ['}']
  for c in cipher[::-1]:
      out.append(chr((ord(c) - 2*ord(out[-1])) & 0xFF))
  flag = "".join(reversed(out))
  ```
- **Trap:** แก้จาก HEAD ไม่แน่นอน เนื่องจาก `2b mod 256` มี 2 วิธีแก้ปัญหา (b และ b+128); ข้อความธรรมดามักจะมีคำนำหน้าแบบสุ่ม (ลบ N ไบต์แรกตามหัวข้อ)

### 1.7 แพ็คเกจ Enigma + IPsec/ESP

-  **การระบุ:** pcap มีแพ็คเก็ต ESP (IPsec) + สตริงตัวพิมพ์ใหญ่ที่ไม่มีความหมาย A–Z พร้อมบรรทัดการกำหนดค่าโรเตอร์ → ถอดรหัส ESP ก่อน และ Enigma วินาที
-  **วิธีแก้ปัญหา:** แก้ไขไฟล์เมจิกปลอม (ส่วนหัว ZIP ของ MS-DOS ปลอม, pcap ที่เสียหาย `PK`/`\xd4\xc3`...) → Wireshark ถอดรหัส ESP ด้วยคีย์ที่พบ → HTML ที่มีข้อความไซเฟอร์เท็กซ์ + การกำหนดค่า Enigma (ตัวสะท้อนแสง, ล้อ, ตำแหน่ง, ปลั๊กบอร์ด) → ป้อนอย่างถูกต้องในโปรแกรมจำลอง (สมมาตร Enigma: เข้ารหัส = ถอดรหัส) งานของนักแก้ปัญหาคือการรับรู้และป้อนการกำหนดค่าที่ถูกต้อง ไม่ใช่เพื่อถอดรหัส
- **กับดัก:** ตรวจสอบเมจิกไบต์สำหรับไฟล์ทั้งหมดก่อนที่จะเชื่อถือส่วนขยาย รูปภาพ EXIF ​​มีรหัสผ่าน ZIP

## 2. ทำเอง / ใช้ Symmetric ไม่ถูกต้อง

### 2.1 ChaCha — 8 ไบต์เทียบกับ 12 ไบต์

-  **การระบุตัวตน:** คำใบ้ตลกๆ เช่น "chacha... อายุ 20 ปี" + ขึ้นอยู่กับคีย์ 256 บิตที่เพียงพอ + nonce + ไซเฟอร์เท็กซ์ → ไม่ใช่การโจมตี เพียงแค่ต้องใช้การเข้ารหัสที่ถูกต้อง
- **วิธีแก้ปัญหา:** ระบุ 16 คำ = ค่าคงที่ 4 ค่า "ขยาย 32 ไบต์ k" (`0x61707865, 0x3320646e, 0x79622d32, 0x6b206574`) + คีย์ 8 คำ + ตัวนับ + nonce 20 รอบ = 10 รอบคู่ (คอลัมน์ + เส้นทแยงมุม) แต่ละรอบ 4 QUARTERROUND (XOR, บวก mod 2³², rotl 16/12/8/7); ในที่สุดบวกสถานะการส่งต่อฟีดดั้งเดิมจากนั้น XOR ด้วยไซเฟอร์เท็กซ์
- **กับดัก:** 8 ไบต์ nonce = Native ChaCha (DJB) ไม่ใช่ RFC 7539 (12 ไบต์) — ต้องปรับไลบรารีเริ่มต้น 12 ไบต์ ถ้าไซเฟอร์เท็กซ์สั้นกว่าบล็อก 64 ไบต์ ตัวนับจะไม่เพิ่มขึ้น

### 2.2 CBC — ไบต์คีย์หายไป 2 ไบต์, IV ล้มเหลว

-  **การระบุ:** CBC + ให้ข้อความธรรมดาที่ไม่เสียหาย ≥ 2 บล็อก + รู้คีย์นำหน้า + บล็อกไซเฟอร์เท็กซ์สุดท้ายที่ไม่เสียหาย → แก้ CBC แบบย้อนกลับเพื่อตรวจสอบคีย์และอนุมาน IV
-  **วิธีแก้ปัญหา:** ความสัมพันธ์ระหว่าง `C_(i−1) = D_k(C_i) ⊕ P_i` และ `IV = D_k(C_0) ⊕ P_0` Brute 2 ไบต์ที่หายไป (ตัวเลือก 65,536 ตัว), **ตั้งค่า IV = เป็น 0 เมื่อ brute** (IV เข้าร่วมใน XOR เท่านั้น ไม่ส่งผลต่อการตรวจสอบ) ตรวจสอบไบต์ที่รู้จักของบล็อก 1 ในแบบย้อนกลับ
- **กับดัก:** XOR อย่างถูกต้อง `decrypt ⊕ plain` ไม่ใช่เข้ารหัส เพียงตรวจสอบออฟเซ็ตที่ทราบ ซึ่งอาจขาดตัวเลือก — ใช้บล็อก 2 เพื่อตรวจสอบเพิ่มเติม

### 2.3 มัลแวร์ exfil — เข้ารหัส 2 ไบต์/1 ไบต์ + ปุ่มคำ XOR/ADD

- **การระบุ:** ข้อมูล exfil "เช่น base64" แต่ยาวสองเท่า (2 ไบต์สำหรับ 1 ไบต์ข้อความธรรมดา) + ไบนารี่พร้อมอาร์เรย์คีย์ฝัง ~ 40 ไบต์
-  **วิธีแก้ปัญหา:** โดยทั่วไปจะเป็นการเข้ารหัสแบบ 2 ไบต์พร้อมการสุ่มซึ่ง **แต่ละไบต์เอาต์พุตจะมีการรั่วไหล 4 บิตพอดี**: `m[i] = (src[2i+1] & 0xf) | ((src[2i] & 0xf) << 4)` → ไม่จำเป็นต้องใช้ brute seed จากนั้นถอดรหัสเลเยอร์การเข้ารหัสแบบโฮมเมด (แต่ละบล็อกขนาด 8 ไบต์: คีย์ XOR ของคำ 32 บิตแรก, คีย์ PLUS ของคำที่สอง; คีย์วนรอบ 10 คำ) → กู้คืนไฟล์ ระบุไฟล์จริง (XLSX ไม่ใช่ XLS — ส่วนหัวที่แตกต่างกัน!) ก่อนที่จะเขียนบรรทัดเดรัจฉาน
- **กับดัก:** ส่วนหัวที่ระบุไม่ถูกต้อง (XLS กับ XLSX) แสดงผลบรรทัดเดรัจฉานไร้ประโยชน์ วิเคราะห์โครงสร้างบิตรั่วก่อนเมล็ดเดรัจฉาน 32 บิต

### 2.4 ฟังก์ชั่นทรงกลม Feistel = XOR

- **การระบุ:** สำหรับข้อความธรรมดาคู่ – ข้อความไซเฟอร์เท็กซ์ + การเข้ารหัส "รอบ Feistel N" ที่มีฟังก์ชันการปัดเศษแบบอ่อน (XOR/ADD) และจำนวนรอบที่ไม่ได้กล่าวถึง → การขยายพีชคณิตเพื่อค้นหาคุณสมบัติ TERMINAL ไม่จำเป็นต้องกู้คืนแต่ละคีย์แบบกลม
- **วิธีแก้:** เมื่อ F คือ XOR กับ round key แบบ deterministic (และนำคีย์กลับมาใช้ซ้ำระหว่างข้อความ) การคลี่สมการจะแสดงว่าแต่ละครึ่งของ ciphertext อยู่ในเซตจำกัด `{pt1, pt2, pt1⊕pt2} ⊕ (ผล XOR ของ round key บางชุด)` และ state จะวนซ้ำด้วยคาบสั้นตามจำนวนรอบ จึง brute-force ผล XOR ของตัวเลือก plaintext × ciphertext × round-key-XOR แล้วกรองเฉพาะผลที่พิมพ์ได้
- **กับดัก:** อย่าไปตามทิศทางหลักของการกู้คืน — มันให้ข้อมูลไม่เพียงพอ คิดว่า "ชุดค่าที่เป็นไปได้" แทนที่จะเป็น "ค่าที่แท้จริง"

### 2.5 CBC ตัดและวาง (บล็อกงานฝีมือถึงผู้ดูแลระบบ)

- **การระบุตัวตน:** 2 คุกกี้/ตั๋วที่เข้ารหัส AES-CBC พร้อมด้วยข้อความธรรมดาที่เกือบจะเหมือนกัน (ความท้าทายและตั๋ว) เข้าสู่ระบบเพื่อควบคุมฟิลด์ชื่อผู้ใช้
- **วิธีแก้ปัญหา:** เลือกชื่อผู้ใช้ที่มีความยาวตรงกันเพื่อบล็อกอย่างเหมาะสม: `'X'*k + '{"user":"x","groups":["admin"]}'`; ใช้คุกกี้ท้าทาย **ตัดบล็อกแรก (IV)** ถอดรหัสที่เหลือเป็นตั๋วผู้ดูแลระบบที่ถูกต้อง (เซิร์ฟเวอร์ตั๋วข้อความธรรมดา)
- **กับดัก:** จำเป็นต้องรู้การตรวจสอบเซิร์ฟเวอร์รูปแบบ JSON ที่แน่นอน ความยาวของชื่อผู้ใช้ต้องดันเพย์โหลด JSON ไปยังขอบเขตบล็อกที่ถูกต้อง

## 3. อาร์เอสเอและตัวเลขวิทยา

### 3.1 โมดูลัสพลิก 1 บิต

-  **การระบุ:** คำใบ้ "หายไป 1 บิต" + ปัจจัย n มีมากกว่า 2 ปัจจัย (ไม่ใช่เซมิไพรม์) → ปัจจัยพลิก 1 บิตใน n; ไซเฟอร์เท็กซ์เข้ารหัสด้วย n REAL
-  **วิธีแก้ปัญหา:** ตำแหน่ง Brute 256 บิต ตัวเลือกที่ถูกต้องคือ = และตัวประกอบจะสร้างจำนวนเฉพาะ 2 ตัวพอดี **เคล็ดลับความเท่าเทียมกัน:** โมดูลัส RSA ที่แท้จริงจะเป็น ODD เสมอ → n ในปัญหาเป็นเลขคู่ ลองใช้ `n | 1` (ตั้งค่าบิตสุดท้าย) ทันทีก่อนตำแหน่ง brute 256
- **Trap:** ถอดรหัสตำราเรียนโดยไม่มีช่องว่างภายใน (ด้วย PKCS#1 v1.5, ตัดหลังจากไบต์ 0x00); ด้วย n ~ 256 บิต factordb/sage factor แทบจะทันที — อย่าเขียนปัจจัยของคุณเอง

### 3.2 เปิดเผยคีย์ RSA สาธารณะ/ค่าเริ่มต้น

-  **การระบุตัวตน:** ดู `rsautl -encrypt` + คำใบ้เกี่ยวกับเครื่องมือ/โครงการที่มีชื่อเสียง (ที่เก็บคีย์, Snakeoil CA, ตัววิเคราะห์แพ็คเก็ต, Python, Debian RNG) → อย่า "ทำลาย RSA" ให้ไปหา **คีย์สาธารณะส่วนตัว** ที่เกี่ยวข้อง
- **วิธีแก้ (ลำดับซ้อนที่พบบ่อย):** รหัสผ่าน ZIP = รหัสผ่านค่าเริ่มต้นที่มีชื่อเสียงของ Java keystore (ใช้ซ้ำทุกระดับ); คีย์ "snakeoil CA" ใน repo apache-mod-ssl; คีย์ `rsa-p-lt-q.key` ใน Wireshark repo (เลือกตามเงื่อนไข p<q); `Lib/test/ssl_key.pem` ใน repo CPython; ระดับสุดท้ายใช้ชุดคีย์ Debian-OpenSSL weak PRNG (ชุด tarball ที่รู้จักกัน) ซึ่งต้องลองหลายพันคีย์ ซ่อน error ด้วย `2>/dev/null` และรวบรวมผลที่ไม่ซ้ำด้วย `sort -u`
- **กับดัก:** ลำดับและเงื่อนไขการเลือกคีย์ (p<q) อยู่ในคำแนะนำ Tarball คีย์ Debian ต้องใช้เวอร์ชันมาตรฐานตามห้าบันทึกในปัญหา

### 3.3 โมดูลัสยักษ์สมดุล → แฟร์มาต์

-  **ระบุ:** โมดูลัส RSA รูปแบบ LARGE ขนาดใหญ่ผิดปกติ (8192 บิต) ที่ factordb ไม่มี → ลอง **Fermat** (p, q อยู่ใกล้กัน) ก่อนที่จะคิดโจมตีโครงสร้างที่ซับซ้อน โดยปกติแล้วเอาต์พุตจะเป็น `q = next_prime(p)`
- **วิธีแก้ปัญหา:** เฟอร์แมตจาก `a = ceil(√N)`, N = a²−b² มาบรรจบกันหลังจากเพียงไม่กี่ขั้นตอน (p−q แตกต่างกันเพียงไม่กี่พันเท่านั้น) ดูโค้ด 5 บรรทัดใน `cheatsheet-asymmetric.md` ส่วนที่ 2.2 จากนั้น `d = e⁻¹ mod lcm(p−1, q−1)`; `pow(c, d, N)` → ฐานสิบหก → ASCII
- **Trap:** PARI/GP `factorint` ไม่มีขั้นตอน Fermat แรก — ด้วย N ที่สมดุล 8192 บิต มันจะค้างตลอดไป ต้องรัน Fermat python แยกกัน

### 3.4 หลายโมดูลัสถูกจัดสรรให้กับไพรม์ทั่วไป

- **การระบุ:** กุญแจสาธารณะ (PEM) หลายอันที่ออกให้กับ "อุปกรณ์" หลายเครื่อง + เอนโทรปีแหล่งที่มาของการสร้างไพรม์ที่ไม่ดี
- **โซลูชัน:** คู่ GCD แบทช์; gcd ≠ 1 → p → q = n/p → ถอดรหัสทั้งสองคีย์ รหัสใน `cheatsheet-asymmetric.md` ส่วนที่ 3
- **กับดัก:** บางคู่แชร์มากกว่า 1 ไพรม์ → gcd คอมโพสิต; ตรวจสอบ `bit_length`/`isprime` ก่อนใช้งาน

### 3.5 md5 จากบรรทัดการถ่ายโอนข้อมูลฐานสิบหก

- **การระบุ:** แต่ละบรรทัดของไฟล์ (ข้อความ hexdump) ถือเป็น "แฮช MD5" สำหรับการค้นหาฐานข้อมูลแบบย้อนกลับ → เดรัจฉานแต่ละบรรทัดผ่านบริการแฮชแบบย้อนกลับในเครื่อง
- **วิธีแก้ปัญหา:** เส้นแยก → สืบค้น Reverse-hash (local rockyou) → เชื่อมต่อผลลัพธ์ตามลำดับ
- **กับดัก:** บรรทัดที่ซ้ำกัน; ผลลัพธ์ต้องมีแถบช่องว่าง

## 4. นิติเวชและสเตโกหลายชั้น

### 4.1 VM Windows + BitLocker + JS ทำให้สับสน + สเตโก

- **ระบุ:** ดิสก์ Windows VM พร้อม BitLocker + หน้า HTML พร้อม JS ทำให้สับสนด้วยอาร์เรย์ตัวเลข → deobfuscate JS (XOR) ก่อนที่จะคิดถึง stego
- **วิธีแก้ (ลำดับที่พบบ่อย):** ใช้ Ophcrack แคร็กรหัสผ่านผู้ใช้ (ห้ามรีเซ็ตรหัสผ่าน เพราะจะสูญเสียความสามารถในการถอรหัส BitLocker) → คีย์ XOR ของ JS คืออักขระแต่ละตัวของ fingerprint สภาพแวดล้อม (`navigator.platform + ...`) → ถอด ASCII85 จาก plaintext (`<~...~>`) เพื่อได้ชื่อเครื่องมือ stego → ใช้เครื่องมือนั้นดึงไฟล์ .doc (รหัสผ่านคือรหัสผ่าน admin ที่ถูกนำมาใช้ซ้ำ) → ถ้าไม่มี Word ให้รันใน sandbox เพื่อเก็บ dump → ค้นหาสตริง base64
- **กับดัก:** การเข้ารหัสอนุกรมสองชั้น (XOR ตามด้วย ASCII85) ลายนิ้วมือขึ้นอยู่กับสภาพแวดล้อมเพื่อสร้างสตริงที่ถูกต้อง

รหัส QR ### 4.2 เสียหายบางส่วน

-  **ระบุ:** รูปภาพ QR ถูกเบิร์น/มุมซ้าย → คิดเสมอว่า **การสร้างใหม่ + การแก้ไขข้อผิดพลาดกก-โซโลมอน** อย่ามองหาธงที่ซ่อนอยู่ด้วยสเตโก
-  **วิธีแก้ปัญหา:** QRazyBox (เครื่องมือบนเว็บ): เลือกเวอร์ชันที่ถูกต้อง (นับจำนวนโมดูลในแต่ละด้าน) วาดโมดูลใหม่ด้วยตนเองที่ยังคงมองเห็นได้ (ตัวค้นหา/เวลา/การจัดแนว + พื้นที่ข้อมูล) → ตัวถอดรหัส RS ของเครื่องมือจะแก้ไขส่วนที่เหลือโดยอัตโนมัติ zbar/zxing การอ่านภาพต้นฉบับล้มเหลวโดยตรง ซึ่งเป็นเรื่องปกติ
- **กับดัก:** เลือกเวอร์ชัน QR ผิด ตัวถอดรหัส = เชื่อมต่อข้อมูลที่ไม่ถูกต้องอีกครั้ง วาดรูปแบบการทำเครื่องหมายที่ถูกต้องก่อน แล้วข้อมูลในภายหลัง

### 4.3 PyInstaller exe

- **ระบุแล้ว:** Windows exe มีร่องรอยของ PyInstaller (magic MEI/pyi-) → แกะรับ .pyc จากนั้น `strings`/`xxd` ก่อนที่จะพยายามถอดรหัส
- **วิธีแก้ปัญหา:** pyinstxtractor → pyc → `uncompyle6`/`decompyle3` (python 3.8-); หากการถอดรหัสล้มเหลว hexdump pyc - แฟล็กมักจะยังคงเป็นสตริงคงที่ในรหัสไบต์
- **Trap:** pyc มีส่วนหัวมายากล STRIP → เพิ่มเวอร์ชันมายากลที่ถูกต้อง (ระบุผ่าน `python3x.dll` ที่รวมอยู่) จากนั้นทำการถอดรหัส ไฟล์นามสกุลใน pcap อาจเป็นของปลอมได้

### 4.4 บูตเซกเตอร์ที่ซ่อนอยู่ใน PDF

-  **การระบุ:** PDF ที่สแกนจะแสดงลายเซ็นการบูต (ส่วนท้าย `55AA`) → แกะสลักระบบไฟล์รูปภาพเพื่อการวิเคราะห์ ไม่ใช่การวิเคราะห์ PDF ปกติ
-  **วิธีแก้ปัญหา:** แยกเซกเตอร์/ดิสก์จากออฟเซ็ตที่พบ → เรียกดู FS เพื่อค้นหาไบนารีแปลก ๆ → ฟังก์ชันตรวจสอบ RE ด้วยสตริงเวทย์มนตร์ + พารามิเตอร์ที่ซ่อนอยู่ (เปรียบเทียบกับเครื่องมือเวอร์ชันสาธารณะดั้งเดิม) → ผลลัพธ์คือค่าส่งคืนของฟังก์ชัน
- **Trap:** คำตอบที่เป็นไปได้ไม่มีการตั้งค่าสถานะ — เป็นเลขทศนิยม (แปลงจากเลขฐานสิบหกที่ส่งคืนของฟังก์ชัน) อ่านคำถามอย่างละเอียด

### 4.5 พอร์ตน็อค

- **การระบุ:** pcap มีการกระจายการเชื่อมต่อไปยังหมายเลขพอร์ตเล็กๆ ที่แปลก → การน็อคพอร์ต; **หมายเลขพอร์ตคือข้อมูล**
-  **วิธีแก้ปัญหา:** จัดเรียงแพ็กเก็ตตามพอร์ตปลายทาง (หรือตามเวลาขึ้นอยู่กับหัวข้อ) → หมายเลขพอร์ตแผนที่ → อักขระ ASCII → รวม
- **กับดัก:** ลำดับที่ถูกต้องคือการประทับเวลา ไม่ใช่การขึ้นหมายเลขพอร์ต — อ่านคำบรรยายของเธรด

### 4.6 กฎ Yara เปลี่ยนเป็น exfil oracle

- **การระบุ:** อินเทอร์เฟซมีเพียง "ส่งกฎ Yara → hit/no-hit" บนไบนารี่บิลด์ RANDOM ต่อการสืบค้น → นี่คือ oracle; จะต้องทำให้แต่ละไบต์รั่วไหลโดยใช้เงื่อนไขของกฎเอง
- **โซลูชัน:** จับคู่ nop-sled 16×`90` + ลำดับไบต์ลักษณะเฉพาะก่อนถอดรหัสการเรียกใช้ฟังก์ชัน อ่านพารามิเตอร์โดยใช้ `uint32(@nops[1]+off)`; เปลี่ยนที่อยู่เสมือน → ออฟเซ็ตไฟล์ผ่านโมดูล `pe` (image_base, virtual_address, ออฟเซ็ตดิบของ `.data`) การเดาแต่ละครั้งจะตรวจสอบ `uint8(flag_raw+i) ^ uint8(key_raw+(i%key_size)) == guess` → พบ = ในไบต์ที่ถูกต้อง วนซ้ำผ่าน flag_len
- **กับดัก:** คนส่วนใหญ่รู้แค่ว่า Yara ตรงกับสตริง/เลขฐานสิบหก — แบบฟอร์มนี้ต้องใช้เลขคณิต + `@`/`[1]` + โมดูล `pe`; ไบนารีใหม่สำหรับแต่ละแบบสอบถาม ดังนั้นทุกอย่างจะต้องลดลงเป็นกฎเดียวที่อ่านทั้งคีย์และแฟล็กออฟเซ็ต

### 4.7 สเตกาโนกราฟแบบความกว้างเป็นศูนย์

-  **การระบุ:** base64 ถอดรหัสข้อความ "สวัสดี ..." ยาวผิดปกติ → ตรวจสอบอักขระที่มีความกว้างเป็นศูนย์ทันที (U+200B/200C/200D)
-  **วิธีแก้ปัญหา:** กรองอักขระตัวพิมพ์เล็ก → คั่นด้วย U+200D (ตัวคั่น) แมป U+200C=0, U+200B=1 → ทุกๆ 8 บิต → ASCII
- **กับดัก:** บางครั้งคุณต้องค้นหาไฟล์เก็บถาวร/บันทึกเก่าของไซต์ (ผ่านรูปภาพ stego ที่บ่งบอกถึงการมีอยู่) — เวอร์ชันดั้งเดิมได้รับการแก้ไขแล้ว

### 4.8 ป้าย RFID EM4100

- **วิธีสังเกต:** ไฟล์ raw bits จาก ProxMark (`Using Clock:64 / Invert:0 / Bits Found:625`, `ASK/Manchester`) → แท็ก RFID 125 kHz มาตรฐาน **EM4100**; การ capture มักมีบล็อก 64 บิตซ้ำหลายครั้ง (แท็กจะส่งข้อมูลซ้ำต่อเนื่อง)
- **วิธีแก้ปัญหา:**
  - แมนเชสเตอร์เร็ว: แต่ละบิตแบ่งออกเป็น 2 ครึ่ง, มีการเปลี่ยนแปลงตรงกลางบิตเสมอ; ทิศทางการเปลี่ยนแปลงค่าบิต = EM4100 เป็นไปตาม IEEE 802.3: ขอบขึ้น = 1, ขอบลง = 0 (G.E. Thomas ในทางกลับกัน) — การถอดรหัสจะไม่ส่งออกเฟรม จากนั้นจะพลิกทั้งหมด (ซึ่งเป็นพารามิเตอร์ `Invert`)
  - Layout EM4100 จริง 64 บิต: `9 bit '1' (header)` + `10 hàng × (4 bit data + 1 parity hàng)` + `4 parity cột` + `1 stop bit 0`
  - Decode: ค้นหาส่วนหัว `data.index("1"*9)` → หมุน `data[off:] + data[:off]` → ตัด 10 กลุ่ม 5 บิตจากตำแหน่ง 9 แต่ละกลุ่มใช้ 4 บิตแรก → hex → UID:
    ```python
    off = data.index("1" * 9)
    r = (data[off:] + data[:off])[:64]
    assert r[:9] == "1"*9 and r[63] == "0"
    uid = "".join("%X" % int(r[9+5*i:13+5*i], 2) for i in range(10))
    ```
- **กับดัก:** สามารถสร้างความเท่าเทียมกันในปัญหาได้ ทางเลือก (ผสมกับคู่/คี่) → อย่าตรวจสอบด้วยความเท่าเทียมกัน สลักการจัดตำแหน่งเท่ากับส่วนหัว 9×'1' + บิตหยุด 0 + UID ที่อ่านได้
- Documents: รหัสแมนเชสเตอร์ (Wikipedia, 2 แบบแผน), Priority1design.com.au (โปรโตคอล EM4100), เอกสารข้อมูล EM4200

## 6. หลักการทั่วไป

1. **เมจิกไบต์ก่อน ขยายทีหลัง** — ไฟล์แปลก ๆ ทั้งหมดจะถูกถ่ายโอนข้อมูลแบบเลขฐานสิบหกด้วย 16 ไบต์แรก
2.  หากคุณแก้โจทย์ N เลเยอร์ ให้แก้แต่ละเลเยอร์ **แต่ละเลเยอร์ใช้เครื่องมือพิเศษ** (binwalk, strings, Wireshark, Simulator...) อย่าเขียนสคริปต์ทั่วไป
